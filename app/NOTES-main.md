## How `wiring.ts` must be completed

It already compiles and is bundled (`npm run build` prints `wiring ok`). What is left is to remove
the casts as the contracts converge:

1. `contracts.ts` mirrors the real shapes today. Each `as unknown as` in `wiring.ts` exists because
   the real classes have private members (so they are not structurally assignable to the narrow
   interfaces) or wider option objects. They are safe but they hide signature drift — re-check
   `wiring.ts` whenever `src/proxy` or `src/sync` changes a signature.
2. `startProxy` is called with `{ gameDir, mirror, port, connectivity, log }`; the real
   `ProxyOptions` also takes `host`, `upstreamBaseUrl`, `upstreamTimeoutMs` — not used.
3. `createBackupManager({ documentsDir, userDataDir, log })` — see the open question about
   `settings.backupsDir` below.
4. `new HttpUpstreamApi({ token, log })` — the token comes from `mirror.readAccount()?.token`, which
   the proxy writes on a successful login. A sync run is skipped entirely when there is no account
   record yet.
5. Once the real modules are considered stable, `fallback-server.ts` can be deleted together with
   the `loadRuntime()` fallback branch in `index.ts` (three call sites, all marked "stand-in").

## Decisions worth knowing

- **Port 47830 already in use.** We hold the single-instance lock first, so a second launch of
  PokeRogue never reaches the server code (it just brings the running window forward). If binding
  still fails with `EADDRINUSE`, it is genuinely another program: one plain message, then exit.
- **Update unpacking uses `tar.exe`** (bsdtar, shipped with Windows 11), falling back to
  PowerShell `Expand-Archive`. A hand-written ZIP reader over `zlib.inflateRawSync` would have to
  get zip64, data descriptors and streaming right for a ~500 MB archive with tens of thousands of
  entries, and a bug there corrupts the game silently. Both fallbacks are part of the OS, so this
  adds no dependency (DESIGN.md §2 is satisfied).
- **The update is swapped in at the next start**, never while the game is running: on Windows a
  folder cannot be renamed while its files are open. `current` → `previous`, `staging/<tag>/unpacked`
  → `current`; `previous` is deleted only after the new build has served one complete session
  (`sessionsSinceInstall` in `<userData>/update-state.json`, incremented on a normal quit).
- **`lastCheckAt` is written before the check runs**, so a failing check still uses up its 6 h slot
  instead of retrying in a loop.
- **Metered detection** asks WinRT (`NetworkCostType` `Fixed`/`Variable`) through PowerShell and
  falls back to `Get-NetConnectionProfile`. Any failure counts as "not metered" and is logged:
  never updating at all is worse than one unexpected download.
- **The conflict window cannot be dismissed** — there is no safe silent default. If it is destroyed
  anyway (app shutting down), `askConflict` rejects, the sync run fails, and nothing is changed on
  either side.
- **`net.isOnline()` is polled every 15 s** plus `powerMonitor` `resume`, because Electron has no
  main-process `online` event; both only trigger `connectivity.probe()`, never a decision.

## Open questions / things other agents must confirm

1. **`lastSyncAt` type mismatch between modules.** `src/proxy/mirror.ts` `readState()` returns
   `lastSyncAt` as an **ISO string**; `src/sync/mirror-port.ts` declares it as a **number**. Both
   compile today only because `wiring.ts` casts. Someone has to pick one (suggestion: ISO string,
   as the proxy already writes it) and fix the other. `contracts.ts` and the settings page accept
   both meanwhile.
2. **`settings.backupsDir` is display-only.** `createBackupManager` takes `documentsDir` and always
   writes to `<documentsDir>/PokeRogue Backups`. The setting therefore only feeds the "Open folder"
   button and is never user-editable in the UI, so today the two agree. If backups should ever be
   movable, `BackupManager` needs an explicit `backupsDir`.
3. **`needs-game-update` has no explicit channel.** `src/sync/errors.ts` classifies it, and I detect
   it by substring in `SyncResult.errors` (`<target>:needs-game-update`) to trigger an immediate
   update check. An explicit callback or a typed field on `SyncResult` would be sturdier.
4. **`unknown-rejection` → "Your progress is safe" notice** is detected the same way, and assumes
   the engine has actually written a backup before giving up. Please confirm that is true, and that
   `unknown-rejection` never fires for an ordinary transport hiccup — the notice should be rare.
5. **Update repository**: `UPDATE_REPO = "m0stey/pokerogue-offline"` (decided 2026-09-12,
   https://github.com/m0stey/pokerogue-offline). The updater expects releases named `game-<tag>`
   with assets `game.zip`, `game.zip.sha256` and `version.json`, and **refuses to install a release
   without a checksum asset**. The repository and its first release still have to exist; until then
   every check just logs a warning and the user sees nothing.
6. **`version.json` is missing from `game-build/dist/game`**, so the settings page shows
   `Game version: unknown` in development and the updater cannot compare tags. `game-build` should
   emit `{"tag": "v1.12.0.11"}` next to `index.html`.
7. **Where is the installer published?** The updater only updates the *game files*. Updating the
   Electron app itself is not implemented (no auto-updater); a new installer would have to be run
   by hand. Confirm that is acceptable, or say so and NSIS + a second release feed can do it.
8. **Unsigned installer.** `signAndEditExecutable: false` (verified as an electron-builder 26 option
   in `app-builder-lib/out/options/winOptions.d.ts`) avoids the winCodeSign symlink extraction
   failure on Windows. Consequence: Windows SmartScreen warns once during setup, as BRIEF.md
   expects. It also means the exe keeps electron's own version metadata.
9. **German or English?** Everything is English (DESIGN.md §3.10 default). The machine's locale is
   German; if she should see German, every string above is in one list ready to translate.

## How `wiring.ts` must be completed

It already compiles and is bundled (`npm run build` prints `wiring ok`). What is left is to remove
the casts as the contracts converge:

1. `contracts.ts` mirrors the real shapes today. Each `as unknown as` in `wiring.ts` exists because
   the real classes have private members (so they are not structurally assignable to the narrow
   interfaces) or wider option objects. They are safe but they hide signature drift — re-check
   `wiring.ts` whenever `src/proxy` or `src/sync` changes a signature.
2. `startProxy` is called with `{ gameDir, mirror, port, connectivity, log }`; the real
   `ProxyOptions` also takes `host`, `upstreamBaseUrl`, `upstreamTimeoutMs` — not used.
3. `createBackupManager({ documentsDir, userDataDir, log })` — see the open question about
   `settings.backupsDir` below.
4. `new HttpUpstreamApi({ token, log })` — the token comes from `mirror.readAccount()?.token`, which
   the proxy writes on a successful login. A sync run is skipped entirely when there is no account
   record yet.
5. Once the real modules are considered stable, `fallback-server.ts` can be deleted together with
   the `loadRuntime()` fallback branch in `index.ts` (three call sites, all marked "stand-in").

## Decisions worth knowing

- **Port 47830 already in use.** We hold the single-instance lock first, so a second launch of
  PokeRogue never reaches the server code (it just brings the running window forward). If binding
  still fails with `EADDRINUSE`, it is genuinely another program: one plain message, then exit.
- **The app installs nothing** (scope trim, 2026-09-13). The updater used to download `game.zip`,
  check its SHA-256, unpack it with `tar.exe`, and swap `current` → `previous` at the next start.
  All of that is deleted, together with the `staging`/`previous` folders, the swap-repair logic in
  `game-files.ts`, the metered-connection detection and its prompt, and the `allowMeteredDownloads`
  / `gameUpdateChannel` / `lastSeenGameTag` settings. A new game version is a new installer.
- **`lastCheckAt` is written before the check runs**, so a failing check still uses up its 6 h slot
  instead of retrying in a loop.
- **One "new version" message per app start, from three sources.** The proxy seeing a save newer
  than the served build, `SyncResult.needsGameUpdate`, and the release feed all mean the same thing
  to her, so `index.ts` funnels them through `showGameUpdateNotice()` behind a single flag.
- **The conflict window cannot be dismissed** — there is no safe silent default. If it is destroyed
  anyway (app shutting down), `askConflict` rejects, the sync run fails, and nothing is changed on
  either side.
- **`net.isOnline()` is polled every 15 s** plus `powerMonitor` `resume`, because Electron has no
  main-process `online` event; both only trigger `connectivity.probe()`, never a decision.
- **Our pages get their German through IPC**, not baked into the HTML, so `strings.de.ts` really is
  the only place words live. The splash has no preload, so its one sentence travels in the query
  string and `splash.js` prints it (its CSP allows `script-src 'self'` only, so no inline script).
- **`safeStorage` is touched in exactly one file**, `src/main/secret.ts`. The Mirror in `src/proxy`
  takes a `SecretCodec` and stays Electron-free, which is also what makes it testable.

## Open questions / things other agents must confirm


*(3, 4, 5, 6 and 9 from the previous round are settled — see the 2026-09-13 scope trim in
DECISIONS.md and `reports/hardening.md`. `SyncResult` now has typed `needsGameUpdate` and
`unrecoverable` fields and nothing matches on error strings; the engine writes a `rejected` `.prsv`
before reporting an unknown rejection; the updater no longer installs anything, so it needs no
assets beyond the tag; `version.json` is emitted and carries both `tag` and `gameVersion`; the UI is
German.)*

1. **`lastSyncAt` type mismatch between modules.** `src/proxy/mirror.ts` `readState()` returns
   `lastSyncAt` as an **ISO string**; `src/sync/mirror-port.ts` declares it as a **number**. Both
   compile today only because `wiring.ts` casts. Someone has to pick one (suggestion: ISO string,
   as the proxy already writes it) and fix the other. `contracts.ts` and the settings page accept
   both meanwhile. Still open.
2. **`settings.backupsDir` is display-only.** `createBackupManager` takes `documentsDir` and always
   writes to `<documentsDir>/PokeRogue Backups`. The setting therefore only feeds the "Ordner
   öffnen" button and is never user-editable, so today the two agree. Still open, and deliberately
   so: a movable backups folder is one more thing to get wrong.
3. **`OWNER_NAME` in `strings.de.ts` is a guess** (`"Alexander"`). It is the only name in the app and
   it appears in the one message that tells her who to ask for a new version. Confirm the spelling
   she would recognise.
4. **No `game-<tag>` release exists yet.** Until the owner dispatches the Actions workflow once, the
   update check finds nothing, logs it, and shows nothing — which is the correct behaviour, but it
   means the release-feed half of the notice has never run against a real feed.
5. **Where is the installer published?** Updating the app itself is not implemented and no longer
   planned: a new version is a new installer, run by hand. Confirm that is how it will be handed
   over.
6. **Unsigned installer.** `signAndEditExecutable: false` (verified as an electron-builder 26 option
   in `app-builder-lib/out/options/winOptions.d.ts`) avoids the winCodeSign symlink extraction
   failure on Windows. Consequence: Windows SmartScreen warns once during setup, as BRIEF.md
   expects. It also means the exe keeps electron's own version metadata. See SECURITY.md.
7. **The German NSIS installer has not been built.** `installerLanguages: de_DE` / `language:
   "1031"` are the right option names for electron-builder 26 (checked in
   `app-builder-lib/out/targets/nsis/nsisOptions.d.ts`), but `npm run dist` has still never been
   run, so the German setup screens have not been seen.
8. **`SyncResult.summary` is still English.** Nothing shows it to the user today; if a status line is
   ever added it has to be translated with the rest.
